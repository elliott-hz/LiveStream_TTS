### 2. 关键发现

- **"文字回复"官方API是全行业空白** — 没有任何直播平台提供"以主播身份发送文字消息"的官方接口。现有方案均为中控台模拟/抓包
- **弹幕采集严重分化** — 仅抖音和淘宝有官方API；京东/拼多多靠第三方wss抓包；视频号/小红书/唯品会完全不可行
- **合规风险需重点评估** — 无人直播封禁（抖音/京东）、抓包被封（京东/拼多多）、AI回复违规（所有平台）

### 3. 架构建议

各平台适配器实现"能力协商"机制：

```
抖音Adapter:   [推流✅] [弹幕✅] [弹品✅] [文字回复⚠️]
淘宝Adapter:   [推流✅] [弹幕✅] [弹品✅] [文字回复⚠️]
快手Adapter:   [推流✅] [弹幕✅] [弹品⚠️] [文字回复⚠️]
京东Adapter:   [推流✅] [弹幕⚠️] [弹品⚠️] [文字回复⚠️]
拼多多Adapter: [推流✅] [弹幕⚠️] [弹品⚠️] [文字回复⚠️]
```

上层业务根据能力矩阵做降级：没有弹幕API的平台降级为纯推流模式。

## 第二部分：智能回复技术方案

### 1. 文字回复：LLM + RAG，不需要训练模型

```
观众弹幕 → 意图分类 → 知识库检索(RAG, Milvus) → LLM 生成回复(DeepSeek API) → 输出文字
```

- **意图分类**：轻量NLP模型（FastText/albert-tiny），本地CPU推理，5秒批处理窗口内完成
- **知识库检索**：商品详情/FAQ/直播脚本 → Embedding → Milvus向量搜索
- **LLM 生成**：调用 DeepSeek API，System Prompt 注入商品信息和回复风格
- **不需要模型训练**：99% 场景只需 Prompt 工程 + 知识库建设

### 2. 语音回复：TTS API，基础能力不需要训练

```
文字回复 → TTS 引擎(CosyVoice) → 音频流 → FFmpeg 混入推流音频
```

两种模式：
| 模式 | 原理 | 效果 |
|------|------|------|
| **原音频驱动** | 从预录视频中提取真人语音片段，拼接成回复 | 音色自然但衔接生硬 |
| **TTS 驱动** | 文字 → CosyVoice API 合成语音 | 任意文字可读，通用音色 |

音色克隆是 Phase 3 的事（需 5-10 分钟音频样本训练），基础 TTS 直接 API 调用即可。

### 3. NLP 本地 CPU 方案

两个任务分阶段处理：
```
弹幕 → Stage 1: 敏感词过滤(AC自动机, ~0.01ms/条) → Stage 2: 意图分类(FastText, ~0.5ms/条) → 路由决策
```

| 模型 | 大小 | 单条推理 | 单核QPS | 12核QPS |
|------|:---:|:---:|:---:|:---:|
| FastText | ~10MB | ~0.5ms | 2,000 | 24,000 |
| albert-tiny | ~16MB | ~5ms | 200 | 2,400 |

大促峰值验证（500路 × 100条/min = 4,167条/5秒批）：FastText 12核并行 ~175ms 完成，3台4C8G冗余部署可撑到2000路。

## 第三部分：视频 AI 解析方案对比

### 1. 两套技术路线

| 步骤 | 方案A：全API | 方案B：GPU自建 |
|------|------|------|
| ASR语音识别 | 阿里云ASR API · 3min · ¥3.5 | Whisper large-v3 T4 · 6min |
| 场景/商品边界 | 阿里云智能媒体API · 15min · ¥7.5 (准确率~70%) | CLIP ViT-L/14 T4 · 10min (准确率~90%) |
| 脚本清洗 | DeepSeek API · 30s · ¥0.001 | DeepSeek API（相同） |
| 视频切割 | FFmpeg stream copy · 2min · CPU | FFmpeg stream copy（相同） |
| TTS音色提取 | CosyVoice API · 5min · ¥1 | CosyVoice2 T4 · 5min |

### 2. 三条成本路线

| 维度 | 全API | 自建GPU | 云GPU竞价 |
|------|------|------|------|
| **前期投入** | ¥0 | ¥285,000 | ¥0 |
| **月费(3000视频/周)** | ~¥158,000 | ~¥19,900 | ~¥18,800 |
| **年成本** | ~¥190万 | ~¥52万 | ~¥23万 |
| **三年成本** | ~¥570万 | ~¥100万 | ~¥68万 |
| **场景检测准确率** | ~70% | ~90% | ~90% |
| **伸缩性** | 无限 | 硬件限制 | 加钱即可 |

### 3. 推荐路径

```
PoC 验证 → 云GPU竞价实例跑100个视频验证效果 → 月费~¥2,000
量起来后 → 自建8-12张T4 → 第一年回本（vs API），之后纯赚
永远不推荐 → 全API长期跑（三年成本570万 vs 自建100万，6倍差距）
```

五家主要平台（覆盖~78%份额）均具备完整商品API能力。

### 2. 核心挑战

"同步"≠"一键复制"，需要解决：
- **类目映射**：每平台类目路径完全不同（如"连衣裙"在不同平台路径差异大）
- **属性转换**：尺码（自定义 vs 平台枚举 vs 标准尺码号）、材质、颜色的规范不一致
- **图片规范**：主图数量/白底图/比例/大小要求各不同
- **审核规则**：极限词检测（淘宝）、AI自动审核（抖音）、低价引流严查（拼多多）

### 3. 分阶段策略

| 阶段 | 方向 | 说明 |
|------|------|------|
| Phase 1（当前） | 平台→我们 | 从平台抓取商品详情作为AI知识库 |
| Phase 2（中期） | 我们→平台 | 选择商品+目标平台→一键发布 |
| Phase 3（远期） | 全渠道双向 | 实时库存/价格同步，建议直接集成聚水潭 |
