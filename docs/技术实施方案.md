### 为什么是"模块化单体"而非微服务？

| 维度 | 模块化单体 | 微服务 |
|------|:---:|:---:|
| 开发速度 | 快（无服务间通信开销） | 慢（需管理RPC/Kafka） |
| 部署复杂度 | 低（1个进程） | 高（8+进程、服务发现） |
| 调试效率 | 高（单进程调试） | 低（跨服务追踪） |
| 资源消耗 | 低（共享内存） | 高（每服务独立资源） |
| **适用阶段** | **0→1 验证期（当前）** | 100+路规模化后 |

PoC 阶段客户量 < 100，1 个 FastAPI 进程 + 1 个 Celery Worker + 1 个 FFmpeg 管理器完全可以应对。当推流路数 > 200 时，将 FFmpeg/Stream 模块拆为独立服务即可。

class User(Base):
    merchant_id: FK(Merchant)
    role: str          # merchant_admin / editor / viewer

```python
class Product(Base):

    name: str          # 标准名称 "法式碎花连衣裙"
    sku: str           # 标准SKU "D001"
    category: str

class ProductKB(Base):
    product_id: FK
    platform: str      # taobao / douyin / kuaishou / jd / pdd
    platform_name: str # 平台商品名
    platform_sku: str  # 平台SKU ID
    price: str
    detail_html: str   # 富文本详情（AI知识库来源）
    last_sync: datetime
```

### 4.3 视频素材与编排

```python
class RawVideo(Base):
    merchant_id: FK
    file_path: str     # MinIO 路径
    duration: int      # 秒
    parse_status: str  # pending / processing / completed
    parse_progress: float  # 0-100

class VideoSegment(Base):    # AI解析后的切片
    raw_video_id: FK
    start_time, end_time: float
    product_id: FK(Product)
    script: str
    status: str        # pending / published

class LiveVideo(Base):       # 编排好的直播视频
    merchant_id: FK
    name: str
    play_mode: str     # sequential / random

class LiveVideoClip(Base):   # 编排中的每个切片
    live_video_id: FK
    segment_id: FK(VideoSegment)
    sort_order: int
    weight: int         # 1-5（重复次数）
    pause_after: int    # 0/3/5 秒
    pause_content: str  # freeze / card / custom
    closeup: str        # 关闭 / 开始3秒后 / 价格播报时 / 全程
    transition: str     # 无转场 / Logo动画 / 关注引导
    overlay: str        # 无贴图 / 商品卡片 / 限时倒计时
    script_override: str # 手动改写的脚本
```

## 五、核心数据流

### 5.1 视频解析管线（异步离线）

```
商户上传视频(OBS/MinIO)
  → Celery 任务入队
  → Step 1: ASR 语音识别（阿里云API, ~3min, ¥3.5/视频）
  → Step 2: 场景/商品边界检测（阿里云智能媒体API, ~15min, ¥7.5）
  → Step 3: LLM 脚本清洗+SKU识别（DeepSeek API, ~30s）
  → Step 4: FFmpeg 无损切割（-c copy, ~2min, CPU）
  → Step 5 (可选): TTS 音色提取（CosyVoice API, ~5min）
  → 通知商户端 → 预览/微调（±秒、改SKU、编辑脚本）
  → 发布到素材库
```

### 5.2 直播推流管线（实时）

```
开播指令
  → 计算播单（权重×顺序/随机 → 切片播放列表）
  → 启动 FFmpeg 子进程：
      - 输入1: concat demuxer（拼接切片视频）
      - 输入2: TTS 音频流（socket fd，初始空）
      - filter: 当TTS输入有数据时，替换视频原音频
      - 输出: RTMP 推流到平台地址
  → 循环播放，直到停播/排班到期
  → 停播: 优雅关闭 FFmpeg 进程
```

### 5.3 AI 互动管线（实时）

```
平台弹幕 WebSocket/API
  → NLP Pipeline:
      Stage 1: 敏感词过滤（AC自动机, ~0.01ms）→ 命中则丢弃
      Stage 2: 意图分类（FastText, ~0.5ms）→ 闲聊不回复 / 提问继续
  → 5秒批处理窗口 → 同类弹幕合并去重
  → RAG 检索（Milvus）→ 商品相关知识片段
  → LLM 生成回复（DeepSeek API, ~1-2s）:
      System Prompt + 知识片段 + 弹幕文本 + 风格指令
  → 文字回复 → 平台聊天区（API/中控台模拟）
  → (可选) TTS 合成 → FFmpeg 混入推流音频
```

## 九、关键风险与缓解

| 风险 | 影响 | 缓解措施 |
|------|:---:|------|
| 场景检测准确率 ~70% | 商户手动微调多 | W4 开始验证，不达标切 CLIP GPU |
| LLM API 成本超预期 | 利润率骤降 | W5 做话术模板匹配+5s批去重减少调用量 |
| FFmpeg 200路稳定性 | 推流卡顿/断流 | W11 压测，单进程管理 + 健康检查 + 自动重连 |
| 平台 API 变更 | 弹幕/推流失效 | 适配器模式快速切换，监控 API 可用性 |
| 无人直播封禁风险 | 直播间被关 | TTS 语音互动降低检测概率，引导商户混合真人值班 |

- API 响应时间 (p50/p95/p99)
